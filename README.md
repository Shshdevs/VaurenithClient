# VaurenithWeb

**VaurenithWeb** — веб-модуль персональной среды управления разработкой и инфраструктурой Vaurenith, разработанный с использованием React, TypeScript и Vite.

## О проекте

**Vaurenith** — единое рабочее пространство для управления программными проектами, Git-репозиториями, исходным кодом, удалёнными устройствами и развёрнутыми сервисами.

**VaurenithWeb** предоставляет браузерный интерфейс для взаимодействия с облачными данными, управления проектами, мониторинга инфраструктуры и визуализации взаимосвязей между программными компонентами и развёрнутыми сервисами.

Основная концепция Vaurenith — **проектно-ориентированный подход**, при котором репозитории, окружения, устройства, контейнеры и сервисы объединяются в единую систему связанных сущностей.

Веб-модуль обеспечивает доступ к возможностям платформы через браузер без необходимости установки отдельного приложения. Доступность операций с локальными ресурсами и удалённой инфраструктурой определяется возможностями подключённых клиентских узлов и серверных интеграций.

## Технологический стек

- **React** — построение компонентного пользовательского интерфейса.
- **TypeScript** — статическая типизация и повышение надёжности кода.
- **Vite** — инструменты разработки и сборки веб-приложения.
- **pnpm** — управление зависимостями проекта.

## Функциональные возможности

Планируемая функциональность веб-модуля:

- **Управление проектами** — создание, редактирование и организация проектов, просмотр связанных ресурсов.
- **Интеграция с Git** — просмотр репозиториев, веток, истории коммитов и изменений исходного кода через доступные интеграции.
- **Управление устройствами** — просмотр зарегистрированных устройств, параметров подключений и их текущего состояния.
- **Удалённый терминал** — взаимодействие с удалёнными системами через предусмотренный защищённый механизм подключения.
- **Мониторинг инфраструктуры** — отображение состояния устройств, системных ресурсов и служб.
- **Управление Docker** — просмотр контейнеров, их состояния, конфигурации и логов, выполнение доступных операций управления.
- **Автоматизация** — управление пользовательскими сценариями и запуск разрешённых операций через подключённые исполнительные узлы.
- **Визуализация архитектуры** — интерактивное представление структуры исходного кода и зависимостей программных компонентов.
- **Карта инфраструктуры** — отображение связей между репозиториями, приложениями, сервисами, контейнерами и устройствами.
- **Облачные данные** — просмотр и изменение пользовательских данных, хранящихся в облачной инфраструктуре Vaurenith.
- **Управление клиентскими устройствами** — просмотр зарегистрированных клиентов и состояния их синхронизации.

Доступность отдельных функций зависит от реализации соответствующих API, подключённых интеграций и прав пользователя.

## Архитектура

VaurenithWeb разрабатывается с учётом принципов модульности, разделения ответственности и Clean Architecture.

Предполагается разделение приложения на следующие архитектурные уровни:

- **Presentation** — страницы, компоненты интерфейса, навигация и отображение пользовательских данных.
- **Application** — пользовательские сценарии, координация операций и управление состоянием приложения.
- **Domain** — бизнес-сущности, правила и контракты взаимодействия.
- **Infrastructure** — API-клиенты, адаптеры внешних сервисов и механизмы браузерного хранения данных.

Бизнес-логика должна оставаться независимой от компонентов React и конкретных реализаций инфраструктурных механизмов.

Исходный код разделён по слоям:

- `src/domain` — будущие бизнес-типы и правила без зависимостей от React и инфраструктуры.
- `src/application` — сценарии приложения и порты, которые определяют необходимые ему внешние возможности.
- `src/infrastructure` — реализации портов, включая HTTP-клиент на Fetch API.
- `src/presentation` — маршрутизация, страницы и React-компоненты.
- `src/app` — composition root: создание инфраструктурных адаптеров и подключение зависимостей к интерфейсу.

Направление зависимостей — `presentation` и `infrastructure` → `application` → `domain`. Конкретные адаптеры подключаются в `src/app`; доменный и прикладной код не импортирует React, Vite или инфраструктурные реализации. Новые функции следует добавлять вертикально по слоям, группируя файлы по предметной области.

На текущем этапе API-слой содержит только общий транспортный контракт. Успешный ответ представлен обёрткой `{ status, message, data }`. `ApiError` описывает HTTP-ошибку и сохраняет код HTTP, статус backend, сообщение, `data` и `X-Request-ID`. `ApiNetworkError` обозначает сетевой сбой, а `ApiProtocolError` — ответ, который не удалось прочитать как ожидаемый JSON-конверт. Поля предметных сущностей, схемы запросов, репозитории и конечные точки будут добавляться отдельно после согласования конкретных функций.

Взаимодействие с серверной частью осуществляется через определённые API-контракты. Веб-модуль отвечает за представление данных и пользовательские сценарии, не дублируя серверную бизнес-логику.

## Локальная разработка

### Требования

- Node.js
- pnpm

### Установка pnpm

Если pnpm ещё не установлен, его можно активировать через Corepack при наличии Corepack в окружении:

```bash
corepack enable
```

### Установка зависимостей

```bash
pnpm install
```

### Запуск сервера разработки

```bash
pnpm dev
```

### Сборка приложения

```bash
pnpm build
```

### Предварительный просмотр сборки

```bash
pnpm preview
```

## Интеграция с Backend

**VaurenithWeb** взаимодействует с серверной частью Vaurenith через API.

Backend обеспечивает авторизацию пользователей, управление облачными данными, синхронизацию и выполнение серверных бизнес-операций.

Веб-модуль отвечает за отправку пользовательских запросов, отображение полученных данных, обработку состояний загрузки и ошибок, а также организацию пользовательских сценариев.

Операции с Git, SSH, Docker и локальными системными ресурсами не выполняются непосредственно в браузере. Для них используются предусмотренные архитектурой клиентские узлы и защищённые механизмы взаимодействия.

Облачный backend не предназначен для предоставления произвольного SSH-доступа к пользовательской инфраструктуре. Доступ к удалённым ресурсам должен осуществляться через отдельно предусмотренный защищённый механизм.

## Запуск

```sh
pnpm install
pnpm dev
```

## Проверки и сборка

```sh
pnpm check
pnpm build
pnpm preview
```

`pnpm check` запускает проверку типов, ESLint, Stylelint и проверку форматирования Prettier.

## Переменные окружения

Скопируйте `.env.example` в `.env`. `PORT` задаёт порт сервера разработки и предпросмотра; по умолчанию используется порт Vite. `VITE_API_BASE_URL` задаёт базовый URL backend API; если он пуст, запросы направляются на тот же origin.

Не добавляйте секреты в переменные `VITE_*`: Vite встраивает их в клиентскую сборку.
