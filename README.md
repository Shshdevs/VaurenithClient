# VaurenithClient

VaurenithClient — веб- и desktop-клиент Vaurenith. Сейчас приложение закрывает базовый пользовательский поток: регистрация и вход через Keycloak, создание или загрузка профиля в Backend и переход на домашний экран.

Клиент использует React-приложение и в браузере, и в оболочке Tauri 2. Интерфейс локализован на русский и английский.

## Что реализовано

- Регистрация и вход через OIDC Authorization Code Flow с PKCE S256.
- Передача подтверждённых данных пользователя в Backend и регистрация клиентского устройства.
- Проверка Backend-сессии при открытии приложения и домашний экран с именем пользователя.
- Адаптеры API для Identity, Session и Projects.
- Получение информации о платформе и версии приложения через платформенный адаптер.

API проектов подключён к приложению, но отдельный экран управления проектами пока не реализован. Пункт «Проекты» в навигации пока служит заглушкой.

## Технологии

React, TypeScript, Vite, Mantine, pnpm и Tauri 2.

## Локальный запуск Web

Требуются Node.js `22.22.2` и pnpm `12.18.0`.

1. Установи зависимости:

   ```sh
   pnpm install
   ```

2. Создай `.env` из примера:

   ```sh
   cp .env.example .env
   ```

3. Заполни переменные окружения:

   | Переменная               | Назначение                                                                                                               |
   | ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
   | `PORT`                   | Порт dev-сервера (по умолчанию `5173`) и preview (по умолчанию `4173`).                                                  |
   | `VITE_API_BASE_URL`      | Базовый URL Backend. Пустое значение использует текущий origin в Web.                                                    |
   | `VITE_OIDC_AUTHORITY`    | URL realm Keycloak.                                                                                                      |
   | `VITE_OIDC_CLIENT_ID`    | Client ID публичного OIDC-клиента.                                                                                       |
   | `VITE_OIDC_REDIRECT_URI` | Redirect URI, зарегистрированный в Keycloak. Если переменная не задана, используется `/auth/callback` на текущем origin. |

   Для браузера укажи Backend в `VITE_API_BASE_URL`, если он работает на отдельном origin. Для Desktop требуется абсолютный URL Backend. Не помещай секреты в переменные `VITE_*`: они становятся частью клиентской сборки.

4. Запусти приложение:

   ```sh
   pnpm dev
   ```

Keycloak должен разрешать Standard Flow с PKCE S256. Redirect URI должен точно совпадать с `VITE_OIDC_REDIRECT_URI`; для браузерного dev-сервера обычно это `http://localhost:5173/auth/callback`. Backend должен быть доступен клиенту и принимать токены настроенного realm. В браузере также проверь CORS для origin приложения.

## Desktop

Для разработки и сборки Desktop нужны Rust stable и системные зависимости Tauri 2 для целевой ОС.

```sh
pnpm desktop:dev
pnpm desktop:build
```

Desktop использует HashRouter и Tauri-адаптер платформы. Сейчас native core предоставляет приложению информацию о платформе и версии клиента. Подробности установки и сборки см. в [руководстве Desktop](docs/desktop.md).

## Проверки и сборка

```sh
pnpm check
pnpm build
pnpm test:e2e
```

`pnpm check` запускает проверку типов, ESLint, Stylelint и Prettier. `pnpm test:e2e` проверяет браузерный поток регистрации в Chrome на изолированных ответах Keycloak и Backend; реальные сервисы для него не нужны.

Для проверки входа с реальными локальными сервисами запусти Keycloak и Backend, настрой `.env` и передай тестовую учётную запись:

```sh
OIDC_E2E_USERNAME='test-user' OIDC_E2E_PASSWORD='test-password' pnpm test:e2e:live
```

Live-сценарий использует `VITE_OIDC_AUTHORITY` из `.env` и проверяет переход через Keycloak и Backend до домашнего экрана.
